# 赞助与项目支持

[English](SPONSORSHIP.md) | [简体中文](SPONSORSHIP.zh-CN.md)

WebCodex 是一个开源项目。资金赞助可以帮助项目持续维护，但长期支持并不只等于捐款，也可以是构建与测试基础设施、代码签名服务、云资源额度、硬件、文档或工程协作。

目标是让支持关系清晰、透明并真正帮助项目，而不是把产品或文档变成广告位。

## 可以怎样支持项目

### 社区赞助

个人或团队可以在项目正式启用相关渠道后，支持日常维护、发布、文档和 Issue 处理。

赞助不购买 roadmap 优先级、安全例外、额外权限，也不会影响代码评审和发布决策。

### 基础设施赞助

WebCodex 需要在 Windows、macOS、Linux、多种架构、Hosted CI 和自托管环境中持续验证，因此基础设施支持尤其有价值。

可能有帮助的资源包括：

- CI 或构建资源；
- macOS、Windows、Linux、x64 与 arm64 测试资源；
- 代码签名或发布基础设施；
- 云计算、存储、带宽或测试环境；
- 用于平台专项验证的硬件。

如果第三方实际提供了这些资源，WebCodex 可以在项目文档或官网中注明相应支持。

### 项目合作

组织可以围绕集成、部署环境、互操作性、测试、文档或其他对更广泛用户有价值的方向提出工程和生态合作。

合作关系不代表背书、排他合作、额外产品权限，也不承诺某项修改一定会被合并。正常的安全、评审、兼容性和发布要求仍然适用。

## 展示原则

赞助商和合作伙伴的展示应与实际支持相称，并且不能干扰 WebCodex 的正常使用。

WebCodex 默认遵循这些原则：

- Runtime 或 Desktop 中不放置侵入式赞助弹窗；
- 不为了赞助归因而额外加入第三方追踪；
- 主要产品界面不放置微信、支付宝等直接收款二维码；
- 赞助方不能控制技术结论、安全策略或发布决策；
- 清晰区分“致谢/支持”与“产品背书”。

合适的展示方式可以包括 README 的 Sponsors 区域、项目官网的 sponsors 页面、发布或基础设施致谢，以及在相关位置克制地展示静态名称或 Logo。

## 当前赞助展示

只有真实、可核实且仍有效的支持关系才应进入赞助列表。在建立合作之前，不应放置占位 Logo，也不应暗示尚不存在的合作关系。

## 如何提出支持

现阶段如希望提供基础设施赞助或项目合作，可以通过仓库 [GitHub Issues](https://github.com/yyjeqhc/webcodex/issues) 说明支持范围以及期望的公开署名方式。不要在公开 Issue 中提交凭据、支付信息、私有访问令牌或其他秘密。

后续如果正式启用个人赞助入口或其他项目联系渠道，可以再补充到本文档中。
